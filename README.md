# dsh-seamless-restart

给 [DeepSeek Harness](https://github.com/deepseek-ai) **桌面版**用的无缝重启。

点一下，DSH 彻底重启一遍。重启那几秒里，窗口被一块**磨砂遮罩**接管——
你最后看到的画面糊化、中间一圈加载、底部一条进度条。窗口看起来像没离开过，
而不是"消失了几秒又回来"。

```
点「重启 DSH」  →  确认  →  窗口变成磨砂加载画面  →  约 5-15 秒后原地恢复
```

## 为什么需要它

DSH 桌面版没有"重启"入口。想让它重开，只能去托盘退出、再点图标——
窗口消失、桌面空一段、有时还得等。

而且 DSH 把"关闭窗口"当成"收进托盘"，所以连"关掉再开"都不顺手：
进程根本没退出，只是窗口不见了。

## 它是怎么做到的

```
POST /dsh-seamless-restart/restart
  → ① 抓旧窗口的矩形 + 截图（PrintWindow，被遮挡也拿得到）
  → ② 在原矩形上起遮罩（磨砂底图 + 居中加载圈 + 底部进度条）
  → ③ 经 explorer.exe 派发重启脚本
  → ④ 它请求外壳关闭 → 短等 → 强制结束 → 等端口释放 → 拉起新实例
  → ⑤ 遮罩看到"旧进程没了 + 新窗口出现"，自己退场
```

几个关键取舍，都有实测依据：

| 决定 | 原因 |
|---|---|
| 截图用 **PrintWindow** 而不是屏幕抓取 | 屏幕抓取拿的是"那个矩形最上层的东西"。DSH 不在前台时会抓到压在它上面的别的窗口。PrintWindow 让窗口自己把内容画进 DC。 |
| 经 **explorer.exe** 派发重启脚本 | 宿主跑在带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object 里，它直接 spawn 的进程会随外壳一起被系统收走。 |
| 重启脚本**主动请求关闭** | DSH 把关闭当收进托盘，进程不会自己退。干等的话要空转 25 秒——这就是"重启要等很久"的来源。 |
| 尺寸测前先声明 **Per-Monitor V2** | 不声明的话读到的是被缩放虚拟化的坐标（实测同一扇窗口：unaware 读 1295×823，真实 1619×1029），遮罩会小一圈、偏一截。 |
| 取窗口用 **EnumWindows 找最大** 而不是 `MainWindowHandle` | 窗口缩小后 `MainWindowHandle` 可能返回某个小面板（实测读到 327×32），遮罩尺寸就全错了。 |
| 全屏时的 `-9,-9 1938×1038` **原样照抄** | Windows 全屏窗口的真实矩形比屏幕每边多 8-9px。裁剪它会让遮罩比窗口窄，露出边缘。 |

## 遮罩的三条铁律

一个更早的实现把机器搞坏过（永远置顶、关不掉、拉不出新窗口），所以这三条是硬约束：

| 铁律 | 为什么 |
|---|---|
| **永不置顶**（代码里不出现 `TOPMOST`） | 遮罩不需要置顶：旧窗口被销毁后，压着它的东西自然没了。为了抢在旧窗口前面而置顶，正是失控的起点。 |
| **随时可关**（不拦 `WM_CLOSE`） | 用户点 X 就退出。关不掉的遮罩比露出空档糟得多。 |
| **硬超时 20 秒** | 到点必退，绝不留幽灵窗口。 |

另外两条编排约束：

- **先截图、再显示遮罩** —— 反过来会把遮罩自己截进去；
- **遮罩绝不阻塞重启** —— 派发后立刻继续。没有遮罩的重启只是多几秒空档，比卡住强。

## 交接判定

「有没有 DSH 窗口」本身是歧义的：旧窗口还活着时它也会匹配。所以分两步：

```
① 等旧 pid 的进程真的消失
② 之后才接受「别的进程有带标题的主窗口」= 新实例画好了
```

顺序反了的话，遮罩刚出现就会被旧窗口自己骗得退场（早期实现实测 72 毫秒就关了）。

## 安装

```sh
dsh plugin --profile desktop add dsh-seamless-restart
```

或者让 agent 用 `plugin_manager`：

```jsonc
{ "action": "install_bundle", "target": "dsh-seamless-restart" }
```

装完**需要重启一次 DSH** 才会加载——就用它自己的按钮。

## 用法

页面上有个「重启 DSH」按钮（桌面壳里在右上角、最小化按钮左边）：

| 操作 | 结果 |
|---|---|
| 点击 | 弹出确认框 → 确认后重启 |
| `Esc` | 关闭确认框，焦点回到对话输入框 |

确认框是页面内自绘的，不是 `window.confirm()`：
原生对话框会阻塞渲染进程，点"取消"之后焦点回不来，输入框会打不了字。

## 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/dsh-seamless-restart/status.json` | 版本、能否重启、识别到的外壳 |
| GET | `/dsh-seamless-restart/ui.js` | 页面脚本本体 |
| POST | `/dsh-seamless-restart/restart` | 发起重启，需要 `x-dsh-restart: 1` |

所有路由先过回环检查、同源检查和 `Sec-Fetch-Site` 检查，再交给宿主信任栅栏。
写路由另要求自定义头：跨站表单带不了它（预检过不了同源校验）。

## 边界

- **重启会中断任务**：会话与项目文件都已落盘，重开后能继续；草稿与终端会丢。
- 只在 Windows 桌面壳下可用；`dsh web` 形态下按钮会隐藏。
- 遮罩是可选的：抓不到截图就用纯色底，抓不到矩形就用上次成功量到的值，都没有就不显示遮罩，重启照常完成。

## 日志

- `$DSH_HOME/seamless-restart/reload.log` —— 挂载、每次重启派发
- `$DSH_HOME/seamless-restart/restart.log` —— 重启脚本每一步（`[relaunch]`）+ 遮罩每一步（`[cover]`）

排查时看这两个文件就够：`requesting graceful close`、`shell gone after force`、
`port free`、`new instance up`、`rect pinned`、`old shell is gone`、`closing: <原因>`。

## 已验证

| 项 | 结果 |
|---|---|
| 遮罩位置（正常窗口） | `rect pinned` 与实际窗口逐像素一致 |
| 遮罩位置（全屏 `-9,-9 1938×1038`） | 原样照抄，四周不露桌面 |
| 遮罩位置（缩小到 900×759） | `EnumWindows` 取最大窗口，尺寸正确 |
| 硬超时 | 设定 12 秒 → 准点退出，日志 `closing: timeout` |
| 可关闭 | 无 `FormClosing` 拦截，点 X 即退 |
| 交接 | 旧进程活着时不误退；新窗口出现才退 |
| 重启耗时 | 主动请求关闭后从 ~25 秒降到 ~5 秒 |

## 已知限制

- 遮罩不置顶。重启瞬间如果你切到别的窗口，遮罩会被盖住——这是刻意的，见上文铁律。
- 遮罩只覆盖旧窗口那块矩形，不是全屏。
- 不做开机自启：那是 [`dsh-ctl-desktop`](https://github.com/ht34robot-173000/dsh-ctl-desktop) 的职责。
